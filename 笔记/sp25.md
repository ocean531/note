##### armor
定义了lighterbar、armor结构体，armor的构造函数接受两个灯条的各种参数，然后计算出装甲版的各种参数 

armor会同时保存xyz_in_gimbal和xyz_in_world，即云台坐标系下的和世界坐标系下的xyz，控制指令需要在云台坐标系下计算，而运动轨迹需要在世界坐标系下预测

##### planner
 planner.get_trajectory():
 获取预测 的轨迹，输入目标，初始角度，弹速
```C++
Trajectory Planner::get_trajectory(Target & target, double yaw0, double bullet_speed)
{

Trajectory traj;

target.predict(-DT * (HALF_HORIZON + 1)); //-0.51t时的状态
auto yaw_pitch_last = aim(target, bullet_speed); 

target.predict(DT); // 此时targe已被更新，所以此时是-0.50t时
auto yaw_pitch = aim(target, bullet_speed);

for (int i = 0; i < HORIZON; i++) {
target.predict(DT);//这里是-0.49t时的target

auto yaw_pitch_next = aim(target, bullet_speed);
auto yaw_vel = tools::limit_rad(yaw_pitch_next(0) - yaw_pitch_last(0)) / (2 * DT);

auto pitch_vel = (yaw_pitch_next(1) - yaw_pitch_last(1)) / (2 * DT);

traj.col(i) << tools::limit_rad(yaw_pitch(0) - yaw0), yaw_vel, yaw_pitch(1), pitch_vel;

yaw_pitch_last = yaw_pitch;
yaw_pitch = yaw_pitch_next;

}
return traj;

}
```
使用中心差分法，中间状态的速度等于后一个状态减去前一个状态再除时间

### USB2CAN设置

创建.rules文件
```
sudo touch /etc/udev/rules.d/99-can-up.rules
```
写入：
```
ACTION=="add", KERNEL=="can0", RUN+="/sbin/ip link set can0 up type can bitrate 1000000"
ACTION=="add", KERNEL=="can1", RUN+="/sbin/ip link set can1 up type can bitrate 1000000"
```
解释：ACTION参数表示发生的动作，“add”表示插入一个设备；KERNEL也是一个判断条件，表示内核名；RUN表示要执行的动作

##### 开启通道
```bash
sudo ip link set can0 up
sudo ip link set can1 up
```

```bash
ip link show //显示接口的信息
```
##### 开启内核
```bash
modprobe can
```
### 坐标系
| **图像坐标系** | 图像左上角 | 水平向右（u） | 垂直向下（v） | —（2D） |

| **相机坐标系** | 相机光心（镜头组内部） | 向右 | 向下 | 向前（光轴方向） |

| **云台坐标系** | 云台 yaw/pitch 旋转轴交点 | 向右 | 向前 | 向上 |

| **世界坐标系** | 云台旋转轴交点 | 指向 IMU 初始化时的 yaw=0 方向 | — | 铅垂向上 |
